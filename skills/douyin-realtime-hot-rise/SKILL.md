# 抖音上升热点（抖音热点趋势选题助手）

[快速开始](https://github.com/allinherog-star/ai-skills/tree/main#%E5%BF%AB%E9%80%9F%E5%BC%80%E5%A7%8B)

[更多技能](https://ai-skills.ai)

### 概述

本技能用于查询抖音正在升温的热点。可按关键词或热点分类筛选，并按当前排名或排名变化查看结果；返回热点词、分类、排名变化、热度值、趋势点和更新时间，帮助判断哪些话题值得进一步跟进并形成选题线索。

### 什么时候使用

**适用场景**

- 用户问「最近抖音什么话题正在升温」「抖音上升榜/飙升榜有哪些热点」
- 用户要查看某个关键词的抖音热度、排名变化或趋势
- 用户按热点分类或关键词筛选上升话题，为选题、运营跟进收集数据

### 调用方式

通过导出的 Python runner 直接调用 AI Skills API：

### 命令示例

**按关键词追热点**

```bash
python3 scripts/run.py --params '{"keyword":"奥运","order":"rank_diff"}'
```

**按分类看热点**

```bash
python3 scripts/run.py --params '{"tag":"5000","order":"rank"}'
```

### 参数说明

| 参数 | 类型 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `tag` | string | 否 | - | 分类 ID；必须使用分类接口返回的数字 ID，多个 ID 用英文逗号分隔，如 `5000,6000` |
| `order` | string | 否 | `rank_diff` | `rank` 按热度排序；`rank_diff` 按排名变化排序。未传时服务端默认按排名变化排序 |
| `keyword` | string | 否 | - | 搜索热点关键词，最多 100 个字符 |

完整机器可读参数结构见 `references/form-schema.json`。

### 参数取值参考

`tag` 只能填分类 ID，不能填“体育”“美食”等名称。分类 ID 可从 AI Skills 的抖音热点分类列表获取；多个 ID 以英文逗号分隔。不要猜测 ID。未选择分类时省略 `tag` 或传空字符串，查询全部分类。

### 支持的输入格式

当前技能直接接收 JSON 参数，不涉及分享链接解析。

### 示例请求

下面的示例参数可直接传给 `scripts/run.py`，runner 会先检查参数格式，再发送给 AI Skills API。

```bash
python3 scripts/run.py --params '{"keyword":"奥运","order":"rank_diff"}'
```

等价的 `--params` JSON：

```json
{
  "keyword": "奥运",
  "order": "rank_diff"
}
```

无效参数会在发起请求前返回可操作的错误提示。例如 `order: "hot"` 应改成 `rank` 或 `rank_diff`；分类名称应换成数字分类 ID；搜索词超过 100 个字符时请缩短后重试。只允许传 `tag`、`order`、`keyword` 三个字段。

### 交付内容

- 上升热点清单：给出关键词、分类、排名变化和热度趋势。
- 趋势判断依据：帮助判断热点是刚开始升温、持续走高还是已经接近峰值。
- 选题参考：可直接用于短视频脚本、内容会选题和赛道观察。

### 结果使用建议

- 优先关注排名变化明显、仍在上升、且与账号赛道匹配的关键词。
- 结合分类和趋势变化判断跟进窗口，尽量把热点转成具体脚本角度。
- 适合内容会、选题池更新和临时热点响应。

### 数据时效与覆盖范围

- 数据来自抖音热点上升榜数据接口；可见分类、条目数和更新时间受数据源覆盖影响，不等同于抖音全站全部内容或所有历史热点。
- 服务端按查询条件缓存结果，缓存周期最长为 24 小时；相同条件的再次调用可能返回缓存。请优先检查 `meta.cached` 和 `data.updateTime`，不要把调用时间当成数据更新时间。
- 每次仅查询第 1 页，数据源最多请求 100 条，技能最多返回 30 条。`pagination.total` 可大于已返回条数；当前不支持输入页码、批量翻页或导出完整榜单。
- 趋势图只展示接口随条目提供的有限趋势点；不提供自定义历史区间、完整历史曲线或长期趋势统计。
- 排名和热度反映榜单数据，不代表内容质量、账号适配度或未来播放量，也不能单独作为流量承诺。

### 选题分析建议

需要深入选题判断时，请基于返回条目按以下步骤给出结论，并明确把数据事实和创作建议分开：

1. 先标明榜单更新时间、是否命中缓存、筛选条件和返回条数。
2. 按 `rankDiff`、`hotScore` 和 `trends` 找出正在上升且热度仍有支撑的词；`rankDiff` 为正表示排名上升，负数表示下降。
3. 结合用户提供的账号赛道、受众和制作能力，说明每个候选话题的匹配理由、可拍角度和主要风险；缺少这些信息时，明确结论只是通用参考。
4. 只用返回的趋势点描述趋势，不外推没有提供的历史数据；不要声称榜单覆盖全部话题。

分页或历史回看需求超出本技能当前能力时，说明限制，并建议缩小关键词或分类范围后重新查询。

### 常见问题

| 现象 | 常见原因 | 处理方式 |
| --- | --- | --- |
| `order` 参数报错 | 值不在允许范围 | 改用 `rank` 或 `rank_diff` |
| `tag` 参数报错或无结果 | 传了分类名称、非数字 ID，或 ID 不存在 | 从分类列表复制数字 ID；多个 ID 用英文逗号分隔 |
| 搜索词报错 | 超过 100 个字符或不是字符串 | 缩短为关键词/短语，并确保 JSON 字符串格式正确 |
| 等待任务超时 | 服务端任务或网络响应过慢；超时不代表任务已取消 | 检查网络后稍后重新查询；避免短时间内重复提交 |
| TLS 证书错误 | 本机 Python 缺少可信 CA 证书 | 安装 `certifi`，或将 `SSL_CERT_FILE` 指向有效 CA bundle 后重试 |
| 结果看起来不够新 | 命中缓存，或数据源尚未更新 | 查看 `meta.cached` 与 `data.updateTime`；最长缓存周期为 24 小时 |
| 返回条数少于 `pagination.total` | 当前只展示首页数据，且技能最多返回 30 条 | 缩小分类或关键词范围；不能通过当前 runner 翻页 |

网络请求单次最多等待 20 秒。异步任务默认最多轮询 180 次、每次间隔 2 秒；可通过 `--poll-attempts` 和 `--poll-interval` 调整，轮询上限分别为 180 次和 30 秒间隔。超时后 runner 会给出重试建议。
